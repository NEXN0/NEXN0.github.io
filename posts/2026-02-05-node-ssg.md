每次用现成的 SSG，我都会在某个时刻打开它的源码，然后在几千行的插件系统里迷路。这一次干脆自己写一个，看看最小可用的版本到底需要多少代码。

答案是：**大概 300 行**，去掉注释和空行之后可能更少。

## 拆解一下要做的事

一个博客生成器的需求其实很有限：

- 读 Markdown，解析 front matter
- 把正文渲染成 HTML
- 套模板，输出文件
- 生成 RSS、sitemap、搜索索引
- 复制静态资源

难点集中在第二件事——Markdown 渲染。剩下的都是文件操作。

## front matter 解析

不需要完整的 YAML，只要支持这种程度就够用了：

```yaml
---
title: 文章标题
published: 2026-02-05
tags: [Node.js, 建站]
category: tech
---
```

对应的解析器可以写得非常直白：

```js
function parseFrontMatter(raw) {
  const m = /^---\n([\s\S]*?)\n---\n?/.exec(raw);
  if (!m) return { data: {}, body: raw };

  const data = {};
  for (const line of m[1].split('\n')) {
    const kv = /^([A-Za-z0-9_-]+):\s*(.*)$/.exec(line);
    if (!kv) continue;
    data[kv[1]] = kv[2].trim();
  }
  return { data, body: raw.slice(m[0].length) };
}
```

## 渲染顺序很重要

在 Markdown 里做内联格式转换，最容易踩的坑是**转义和替换的先后顺序**。正确的做法是：

1. 先把行内代码抽出来，用占位符替换（因为代码里的 `*` 不该变成斜体）
2. 处理反斜杠转义
3. 对整个字符串做 HTML 转义
4. 再做链接、粗体、斜体等替换

顺序错了就会出现 `<script>` 泄漏、或者代码块被格式化成斜体的经典事故。

```js
// 先抽走行内代码
out = out.replace(/`([^`]+)`/g, (_, code) => keep(`<code>${escapeHtml(code)}</code>`));

// 再整体转义
out = escapeHtml(out);

// 最后处理强调语法
out = out.replace(/\*\*([^*]+)\*\*/g, '<strong>$1</strong>');
```

## 构建耗时

| 文章数 | 构建耗时 |
| --- | --- |
| 10 篇 | 12 ms |
| 100 篇 | 68 ms |
| 1000 篇 | 620 ms |

即使文章数上千，构建也在一秒之内。这个量级下，增量构建、缓存之类的东西完全是过度设计。

## 值得保留的克制

写到后面会很想加功能：标签页、分页、相关文章、阅读进度条……每次我都问自己一句——**这个功能现在不用，以后真的会用吗？**

:::warning
不要为了「以后可能用到」而预先设计插件系统。你大概率不会写第二个主题，也大概率不会换渲染器。
:::

最后保留下来的，只有真正在用的东西。这大概也是自己写工具最大的好处：**没有人逼你为别人的需求负责。**
